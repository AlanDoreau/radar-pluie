Appli météo perso d'Alan (en français), nommée **Éclaircie** depuis le 24/11/2026 (avant : Radar Pluie ; le dépôt, l'adresse et les clés localStorage gardent « radar-pluie »), publiée sur **https://alandoreau.github.io/radar-pluie/**.

## Architecture
- `index.html` : toute l'appli (HTML + CSS + JS, carte **MapLibre GL 4.7.1** via unpkg depuis le 24/11/2026 ; avant : Leaflet, dernier commit Leaflet = bdf4c04). Trois onglets, dans cet ordre (choix validé) : **Relevés** (icône emoji 🌡️ + 2 petites gouttes 💧 en haut à droite, choix validé ; onglet d’ouverture), **Prévisions** 🌦️, **Radar** (icône SVG : mini-carte avec une perturbation).
- `scripts/update.py` : robot (Python) lancé par `.github/workflows/radar.yml` ; fabrique `data/frames.json` + images PNG radar/prévision ; appelle `scripts/releves.py`.
- `scripts/releves.py` : relevés pluviomètres Météo-France (DPPaquetObs v2, horaire, 24 h d'historique côté API) + **station virtuelle radar** au-dessus du lieu (cumul des lames d'eau 5 min) → `data/releves.json`. Pluviomètres quotidiens data.gouv désactivés (`departements: []`). Par heure et par station : rr, t, et si mesurés ff/fx (km/h), u, td, dd (`VERSION` dans releves.py : l'augmenter relit les 24 h une fois).
- Station virtuelle du lieu (Verneuil-le-Château) : pluie = radar ; température, humidité, rosée, vent, rafales = modèle AROME via Open-Meteo (`meteofrance_seamless`, current + 24 h passées), côté navigateur, affiché comme « estimé ». Les stations les plus proches (L'Île-Bouchard, Saint-Épain) ne mesurent ni vent ni humidité.
- Onglet Relevés (ordre validé, comme Météus) : en-tête compact (24/11/2026, demande d'Alan) = sous le titre « Dernier relevé HHhMM · n/N stations » (`#relMaj`), bouton ⚙️ à droite de la barre (`#btnChoose`) pour choisir les stations ; « Maintenant » (cartes par station, défilement horizontal ; fond « ciel réaliste » selon le temps (images `ciel/*.svg` à nuages fractals, refaites par `ciel/generer.py`, converties en WebP 800×340 et intégrées en base64 dans le CSS pour un affichage immédiat ; dernier ciel connu gardé dans `radar-pluie-ciel` (3 h) pour ne pas attendre Open-Meteo ; sans emoji, Alan voulait du réaliste), demande d'Alan 24/11/2026 : pluie si la station a mesuré de la pluie sur la dernière heure, sinon `weather_code`/`is_day` AROME du lieu via Open-Meteo → soleil, éclaircies, couvert, pluie, orage, neige, brouillard, nuit, nuit couverte), « La nuit dernière » (22h–6h : pluie, rafale max, mini/maxi), cumuls, graphiques.
- `config.json` : lieu des relevés (Verneuil-le-Château 47.0394, 0.4583, depuis le 23/11/2026 ; avant Marcilly-sur-Vienne), rayon stations 50 km. Changer de lieu garde l’historique des stations ; la station virtuelle radar repart de zéro.
- L'état (historique radar, relevés) est relu à chaque passage depuis le site publié (`PAGES_URL` = sortie de `actions/configure-pages`). Rien n'est commité par le robot.
- Publication : GitHub Pages en mode « GitHub Actions » (upload-pages-artifact + deploy-pages, 2e essai si échec). Si les 2 essais échouent (pannes GitHub Pages « erreur 500 », ex. 25/11/2026 16h50–17h10), le passage n'est compté en échec (→ e-mail GitHub) que si le site publié a plus d'1 h (`generated` de frames.json) ; sinon simple avertissement, demande d'Alan (trop d'e-mails).

## Données
- Radar : Météo-France DPRadar (mosaïque LAME_D_EAU 500 m, HDF5) + DPPaquetRadar ; 2 h 30 de passé (PAST_HOURS ; 1 h 30 avant le 24/11/2026, 2 h avant le 25/11/2026), pas 5 min (RADAR_STEP_MIN, 10 min avant le 25/11/2026, demande d'Alan) ; lissage gaussien ; palette 9 classes (violet ≥ 40 mm/h, choix validé).
- Radar HD autour du lieu (25/11/2026, demande d'Alan « qualité max + chargement rapide », option 1 retenue ; option 2 = radar en tuiles, gardée pour plus tard) : le robot fait en plus une image `data/rh/*.png` à pleine précision (0.005°, ~580×580 px, lissage 1.2 px) sur ±`HD_KM` = 110 km autour de `config.json` lieu, et laisse ce carré vide dans l'image France (`HD_MASK`) ; `frames.json` : champ `hd` par image radar + `hd_bounds`. Prévisions PIAF aussi en HD depuis le 25/11/2026 (`PIAF_HD`, images `data/ph/*.png`, grille 1 km rééchantillonnée à 0.005° avec lissage 1 px (2 px jugé trop flou à côté de Météus), `PIAF_HD_SMOOTH_SIGMA_PX`) ; AROME-PI de secours sans HD. Côté appli : paires de sources `radarA/hdA` et `radarB/hdB` (fondu enchaîné par paire), `rainAt` lit l'image HD si le point est dans son carré. La station virtuelle (`point_values`) lit aussi la grille HD (3×3 px ≈ 1,5 km).
- Prévision radar (25/11/2026, demande d'Alan « comme Météus ») : **PIAF** (Prévision Immédiate Agrégée Fusionnée = radar extrapolé + AROME-PI), API « PrevisionImmediatePrecipitations », `https://api.meteofrance.fr/pro/piaf/1.0/wcs/MF-NWP-HIGHRES-PIAF-001-FRANCE-WCS` (gratuite, abonnement fait le 25/11/2026, clé régénérée), couverture `..._{run}_PT5M` = mm en 5 min (×12 → mm/h, vérifié : PT15M = 3 × PT5M), run toutes les 5 min (en ligne ~10 min après), échéances 5 à 195 min, 0.01°, quota 50 req/min (requêtes espacées de 1,25 s, une par échéance : la requête groupée renvoie 404). FORECAST_HOURS = 2,5 h après la dernière image radar, autant que le passé → « maintenant » au milieu de la barre. Secours si PIAF échoue : AROME-PI (`fetch_forecast`, pas 15 min, runs complets seulement).
- Prévisions 10 jours (côté navigateur) : Open-Meteo `meteofrance_seamless` (J1–J4) sinon `best_match` (ECMWF) ; fourchette = ensemble ECMWF (quartiles) affichée seulement dans le détail ; détail par tranches de 2 h ; vent arrondi à 5 km/h et pluie arrondie au mm (« <1mm » sous 0,5 mm) dans la liste, décimales gardées dans le détail du jour (choix validés). Icône du jour et des tranches de 2 h = `codeRepr` (28/11/2026, Alan voyait un nuage par grand beau temps : avant, on prenait le code le plus fort, une seule heure « couvert » suffisait) : pluie/neige/orage seulement si une heure donne ≥ 0,1 mm, brouillard s'il couvre au moins la moitié des heures, sinon nébulosité moyenne des heures (0–3). Ciel sans pluie (codes 0–3, prévisions + fond du ciel des Relevés) recalculé par `skyCode` depuis `cloud_cover_low/mid/high` (28/11/2026, Alan : « dégagé chez moi, l'appli met couvert ») : couverture = max(bas, moyen, haut × 0,5), car le code Open-Meteo suit la couverture totale où un voile de cirrus pèse autant qu'une couche grise ; seuils 20 / 45 / 80 %. Détail du jour (25/11/2026, Alan signalait des incohérences bandeau radar / tranches) : la pluie Open-Meteo de l'heure h (cumul de h-1 à h) est ramenée à l'heure h-1 pour que la tranche « 18h00-20h00 » parle bien de 18h–20h ; aujourd'hui, la pluie radar au lieu (`radarParHeure` : classes de couleur des images radar + PIAF, `MMH_CLASSE` = moyenne géométrique des bornes) remplace celle du modèle sur les heures couvertes (au prorata si partiel), tranche marquée « (radar) » au lieu du risque ; total « d'ici minuit » et total du jour en tête suivent ; redessin quand les images radar arrivent (`radarHeuresSig` dans `updateHere`).
- Vigilance : `scripts/vigilance.py` (API Données Publiques Vigilance, `cartevigilance/encours`) → `data/vigilance.json` pour le département `departement_vigilance` de config.json (37) ; bandeau en haut de Prévisions seulement en orange/rouge (jaune volontairement non affiché, choix validé), lien vers vigilance.meteofrance.fr.
- Clé Météo-France : secret GitHub `METEOFRANCE_KEY` (en-tête `apikey`), abonnements : DPRadar, DPPaquetRadar, AROME, AROME-PI, PIAF (PrevisionImmediatePrecipitations), DPPaquetObs v2, Données Publiques Vigilance. La clé (JWT, régénérée le 25/11/2026 pour PIAF) ne couvre que les API abonnées au moment où elle est générée : après un nouvel abonnement, régénérer la clé et mettre à jour le secret. Ne jamais demander ni afficher la clé.

## Exécution
- Lancé toutes les 10 min par **cron-job.org** (tâche « Radar Pluie », POST sur l'API `workflow_dispatch`, clé GitHub fine-grained `radar-pluie-cron`, Actions lecture/écriture). Pas de `schedule` GitHub (retiré volontairement). Notification e-mail cron-job.org après 3 échecs d'appel de suite + au retour (ne voit pas les échecs internes du robot).
- Onglet Radar (24/11/2026, façon Pleinchamp) : carte vectorielle pour la fluidité (demande d'Alan) ; fond par défaut « Détaillé » = OpenFreeMap style liberty (vectoriel, gratuit sans clé ; bascule forcée une fois via `radar-pluie-fond-v2`), les autres fonds sont des tuiles raster ; zoom MapLibre = zoom Leaflet − 1 (helpers `Z`, `zoomL`, `setView`), max 15 (= 16 Leaflet) ; radar = deux sources `image` superposées `radarA`/`radarB` (l'image suivante se charge dans la cachée via `updateImage`, une à la fois, puis fondu enchaîné par `raster-opacity-transition`) placées sous les noms de lieux ; appui long maison (touchstart 600 ms) ; secours : si OpenFreeMap ne répond pas (pas de tuile en 10 s ou 3 erreurs), bascule sur « Relief » sans l'enregistrer (réessai à la prochaine ouverture, choix d'Alan) ; vue « chez moi » (`vueMaison`, RECUL_KM = 50 km de chaque côté de la maison) remise à chaque arrivée sur l'onglet Radar, sauf quand la vue vient d'être choisie (`garderVue`), demande d'Alan ; fond « Plan IGN » en plus ; panneau du temps : lecture/pause + ↻ (retour à maintenant + recharge), date + heure, barre verte épaisse, carrés de pluie au point gardés au-dessus (demande d'Alan), sans phrase en dessous (les couleurs suffisent, choix d'Alan), trait rouge = maintenant, partie prévision hachurée ; barre proportionnelle à l'heure réelle (25/11/2026 : avec le pas de 5 min, la barre par numéro d'image donnait 2/3 au passé ; `minOf`/`tpos`, curseur en minutes + `nearestIdx`, carrés de pluie larges selon la durée de leur image) ; animation au rythme du temps réel (MS_PAR_MIN = 50 ms par minute : 250 ms entre images à 5 min, 750 ms entre prévisions AROME-PI de secours à 15 min), fondu = 90 % de l'intervalle, 150 ms quand on glisse le curseur (25/11/2026, demande d'Alan : voir les perturbations se former).
- Logo (24/11/2026, choix d'Alan « B1 » avec gros soleil) : soleil, nuage, 2 gouttes, cercles et balayage radar sur fond bleu ciel #5bb8f5 ; `icon-v2.svg` + `icon-v2-192.png`/`icon-v2-512.png` (rsvg-convert), copiés par le workflow ; noms versionnés (et `manifest.webmanifest?v=2`) pour que les téléphones ne gardent pas l’ancien logo en cache : changer de numéro à chaque nouveau logo.
- Démarrage rapide du radar : essai du 25/11/2026 (service worker `sw.js` qui gardait les images en cache + préchargement ordonné, commit 7570ea0) **annulé** le jour même car Alan signalait un bug ; `sw.js` est maintenant un « désactiveur » (vide le cache, se désinscrit, recharge une fois) : le laisser publié quelques semaines pour nettoyer les téléphones. Cause probable trouvée ensuite (lenteurs signalées sur Relevés et Radar) : `updateHere` relisait toutes les images (~40) à chaque arrivée d'image → le téléphone redécodait sans cesse de grandes images. Corrigé le 25/11/2026 : mémoire `clsMemo` (image + point lus une seule fois), `hereBientot` (mises à jour regroupées, 300 ms), préchargement radar lancé 4 s après l'ouverture, images radar à 0.015° (1100 px de large, `DEG_PER_PX`, lissage 0.9 px) au lieu de 0.010°.
- Côté appli : maison 🏠, lieu, favoris, stations choisies, fond de carte et caches sont dans le `localStorage` du téléphone.
